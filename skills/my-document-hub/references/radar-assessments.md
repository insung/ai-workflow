# 레이더 질문지와 변화 관리

## 역할과 배치

레이더 차트는 한 시점의 인상을 그리는 장식이 아니라, 같은 질문을 반복해 성향이나 위험 노출의 변화를 비교하는 평가 도구로 사용한다.

- 프로필 본문에는 현재 해석과 차트를 둔다.
- 반복 질문, 축 정의, 점수 계산, 답변과 평가 이력은 해당 프로필의 `questionnaires/`에 둔다.
- 차트 파일은 해당 프로필의 `assets/`에 둔다.
- 질문지가 두 편뿐이어도 본문과 갱신 주기가 다르므로 별도 디렉터리를 허용한다.
- 상위 `README.md`가 질문지를 직접 나열하면 `questionnaires/README.md`를 만들지 않는다.

새 질문지는 [radar-questionnaire-template.md](../assets/radar-questionnaire-template.md)를 복사해 시작한다. 템플릿에는 개인 답변이나 실제 점수를 넣지 않는다.

## 질문지 설계

1. 먼저 차트가 답할 질문을 한 문장으로 정한다.
2. 축마다 측정할 성향 하나와 낮은 점수·높은 점수의 방향을 정의한다.
3. 모든 축에서 높은 점수의 의미를 같은 방향으로 맞춘다. 성향 강도 차트와 위험 노출 차트를 섞지 않는다.
4. 한 축에는 서로 다른 상황을 다루는 시나리오 질문을 기본 세 개 둔다.
5. 질문은 추상적인 자기평가보다 실제 선택, 중단 조건, 예외와 자원 배분을 드러내게 쓴다.
6. 질문은 한 번에 하나씩 사용자에게 묻는다. AI가 답을 추정하거나 사용자의 짧은 답을 과도하게 일반화하지 않는다.

## 점수와 신뢰도

각 질문은 낮은 경향 1점부터 높은 경향 5점까지 해석하고 축 점수는 다음 식으로 0점부터 10점까지 환산한다.

$$
AxisScore=2.5\times(\operatorname{avg}(Responses)-1)
$$

점수와 함께 답변 요약, 해석, 평가일과 신뢰도를 기록한다.

- 낮음: 가상 시나리오 하나이거나 서로 충돌하는 답변만 있음
- 중간: 서로 다른 사례가 둘 이상 일관되거나 선택 기준이 구체적으로 확인됨
- 높음: 실제 작업·거래 기록에서 같은 행동이 반복됨

현재 자료가 부족하면 잠정 점수임을 표시한다. 점수는 성과, 능력, 인격 또는 심리 상태의 진단으로 표현하지 않는다.

## 같은 차트 갱신과 새 차트 생성

다음 경우에는 기존 차트의 안정적인 파일명을 유지하고 점수와 평가 이력만 갱신한다.

- 측정 질문과 축의 의미가 같음
- 새 답변이 기존 축의 신뢰도나 점수만 바꿈
- 생활·업무·시장 변화 뒤 같은 성향을 다시 측정함

다음 조건을 모두 만족할 때만 새 질문지와 차트를 제안한다.

1. 기존 축으로 설명하면 의미가 왜곡되는 별도 측정 질문이 있다.
2. 서로 겹치지 않는 새 축을 세 개 이상 정의할 수 있다.
3. 한 번의 답변이 아니라 서로 다른 사례에서 패턴이 반복된다.

질문 문구나 축 정의가 실질적으로 바뀌면 `questionnaire-version`을 올린다. 이전 버전과 비교할 때는 축의 의미와 환산식이 같은지 확인하고, 직접 비교할 수 없으면 별도 기준선으로 시작한다. 한 번의 새 답변 때문에 축을 추가하거나 기존 축의 이름을 바꾸지 않는다.

## 재평가 시점

기본 재평가 주기는 3개월이다. 다음 사건이 있으면 정기 시점 전에도 다시 평가할 수 있다.

- 투자 전략, 최대 비중, 매수·매도 또는 중단 규칙이 크게 바뀜
- 주된 프로젝트, 직업, 가족 또는 주거 조건이 바뀜
- 기존 점수와 모순되는 실제 행동이 반복됨
- 사용자가 차트나 프로필이 더 이상 자신을 설명하지 않는다고 판단함

자동 알림은 사용자가 명시적으로 요청할 때만 만든다. 비교 가능한 평가가 두 번 이상 쌓이고 변화 자체가 의사결정에 도움이 될 때만 별도 추세 차트를 만든다.

## 갱신 절차

1. 프로필 본문, 질문지, 현재 SVG와 열린 코멘트를 읽는다.
2. 마지막 평가 이후의 실제 사례와 바뀐 조건을 확인한다.
3. 아직 답하지 않았거나 신뢰도가 낮은 축의 시나리오를 하나 묻는다.
4. 답변 원문을 보존한 요약, 해석, 점수와 신뢰도를 질문지에 기록한다.
5. 충분한 근거가 있으면 프로필 본문의 해석과 점수를 갱신한다.
6. SVG의 설명, 점 위치와 표시 점수가 본문 표와 같은지 맞춘다.
7. 평가 이력은 덮어쓰지 않고 새 행을 추가한다.
8. 링크, frontmatter, SVG 렌더링과 Tandem 앵커를 검증한다.
