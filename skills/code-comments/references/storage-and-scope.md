# 저장 형식과 다중 저장소 범위

## 확장의 정본 규칙

- 스레드는 저장소별 `.comments/threads/<thread-id>.jsonl`에 append-only 이벤트로 저장된다.
- VS Code 확장과 에이전트는 같은 이벤트 로그를 읽고 쓴다.
- 공식 MCP 서버는 `MD_COMMENTS_ROOT` 또는 프로세스의 현재 디렉터리에서 저장소 루트를 하나 정한다.
- Git worktree는 git common dir를 통해 주 작업 트리의 같은 코멘트 저장소를 사용한다.
- 이벤트 추가는 스레드별 잠금을 사용하고, 앵커·baseline·작성자 형식은 공식 MCP 서버가 관리한다.

## 개인 다중 저장소 보완

상위 작업공간이 여러 Git 저장소를 포함하면 하나의 MCP 프로세스로 모든 저장소를 안전하게 구분할 수 없다. `scripts/comments.js`는 다음 방식으로 이를 보완한다.

1. 현재 저장소와 작업공간 아래의 Git 저장소를 런타임에 발견한다.
2. 조회 결과에 저장소를 붙여 반환한다.
3. 쓰기 대상 저장소를 스레드 ID, 파일 또는 명시적인 `--repo`로 한 곳에 확정한다.
4. 확장의 v2 이벤트 형식과 스레드별 잠금 규칙으로 해당 저장소에 기록한다.

따라서 새 저장 포맷이나 중앙 코멘트 데이터베이스는 만들지 않으며, VS Code 확장과의 호환성을 유지한다.

## 소유권

- 코멘트 원문과 해결 여부는 사용자가 소유한다.
- Codex는 답글과 새 코멘트를 추가할 수 있지만 기존 이벤트를 다시 쓰거나 삭제하지 않는다.
- 해결은 사용자가 VS Code에서 수행한다.
- 커밋, 브랜치와 merge queue는 이 스킬의 범위 밖이다.
