# 이슈 본문 상세

이슈는 매번 만들지 않는다. 사용자가 만들어 달라고 했거나 PR이 닫을 이슈가 아직 없을 때만 이 문서를 읽는다.

## 이슈에 무엇을 적는가

**이 이슈로 무엇을 하려는지와 무엇이 되면 닫는지를 적는다.** 기획 문서를 옮겨 적는 자리가 아니다.

문서 허브에 관련 기획이 있으면 **참고 링크로만** 걸고, 이슈 본문은 이번 조사와 판단으로 채운다. 허브 문서가 없다는 이유로 이슈 생성을 막거나 확인되지 않은 내용을 만들어 넣지 않는다.

## 문체

**존댓말도 반말도 쓰지 않는다.** 산문은 평어(`~다`), 목록 항목과 표 칸은 명사형으로 끝낸다. 자리별 종결과 예시는 [pr.md](pr.md)의 「문체」 절에 있다.

사용자가 말한 증상을 그대로 옮길 때만 예외다. 인용부호로 감싸고 원문을 보존한다.

## 늘 쓰는 두 자리

기능 이슈든 버그 이슈든 **목표와 달성 조건**은 늘 쓴다. 지금 알고 있는 것과 참고 링크는 쓸 내용이 있을 때만 만들고, **절이 없으면 그 항목은 없는 것으로 읽는다.** 빈 절을 「없음」으로 채우지 않는다.

### 기능 이슈

```markdown
## 목표

<!-- 이 이슈로 무엇을 하려는가. 한두 문장 -->

## 달성 조건

<!-- 무엇이 되면 이 이슈를 닫는가 -->

- [ ]
- [ ]
```

- **달성 조건은 확인할 수 있는 형태로 쓴다.** 「사용성 개선」이 아니라 「앱 상세에서 기간을 주 단위로 선택 가능」처럼 쓴다. 이 자리가 나중에 PR의 「확인」 절과 대응된다.

### 버그 이슈

```markdown
## 목표

<!-- 무엇이 잘못 동작하고 있고 어떤 상태가 되어야 하는가 -->

## 재현 절차

Given
When
Then

## 확인한 환경

- 확인한 날짜 :
- 화면 또는 API 경로 :
- 배포 버전 또는 브랜치 :
```

### 쓸 내용이 있을 때만 만드는 자리

| 절 | 만드는 조건 |
| --- | --- |
| `## 지금 알고 있는 것` | 조사·확인한 결과가 있을 때. **확정되지 않은 것은 확정되지 않았다고 적는다** |
| `## 참고 링크` | 문서 허브 문서·Slack 스레드·관련 PR이 있을 때 |

허브 문서는 이 자리에만 들어간다. 필수 칸이 아니다.

## 재현 절차를 사용자에게 묻는 방법

AI는 버그를 목격한 사람이 아니므로 재현 절차를 만들어 낼 수 없다. 사용자가 「이거 안 돼요」 수준으로 말했으면 아래를 묻고, 답을 받은 뒤에 이슈를 만든다.

| 물을 것 | 답이 없으면 생기는 일 |
| --- | --- |
| 어느 화면 또는 어느 API 경로에서 일어나는가 | 확인할 자리를 못 찾는다 |
| 무엇을 하면 일어나는가 | 재현하지 못한다 |
| 무엇이 나와야 하는데 무엇이 나왔는가 | 정상 동작이 무엇인지 판정할 수 없다 |
| 언제 확인했는가 | 이미 고쳐진 것을 다시 파게 된다 |

**추측으로 채우지 않는다.** 답을 못 받은 자리는 비운 채로 두고 무엇이 비었는지 보고한다.

## 제목

커밋과 같은 형식으로 쓴다.

```text
feat(app-ranking): 기간을 주 단위로 선택
fix(dashboard): 위젯 순서가 새로고침 후 초기화
```

버그 이슈는 `fix`, 기능 이슈는 `feat`로 시작한다. 그 이슈를 닫는 PR과 커밋이 같은 scope를 쓰게 되어 나중에 `git log`로 이어 볼 수 있다.

## 하위 이슈로 나누는 기준

달성 조건이 서로 다른 시점에 끝나거나 담당이 갈리면 나눈다. 한 사람이 이어서 하는 작업 단계는 나누지 않고 달성 조건의 체크박스로 둔다.

## 이슈를 만드는 절차

1. 같은 내용의 이슈가 이미 있는지 찾는다. 있으면 새로 만들지 않고 그 이슈를 가리킨다
2. 본문 초안을 대화에 그대로 보여준다
3. 승인받는다
4. 파일로 저장해 `--body-file`로 넘긴다

```bash
gh issue list --state all --search '기간 선택'   # 중복 확인
gh label list                                    # 붙일 label 이름 확인

gh issue create --title 'feat(app-ranking): 기간을 주 단위로 선택' \
  --label '✨ Feature' \
  --body-file /tmp/issue-body.md
```

**중복 확인을 건너뛰지 않는다.** 같은 증상의 이슈가 이미 열려 있는데 새로 만들면 논의가 두 곳으로 갈린다.

**승인 전에 실행하지 않는다.**
